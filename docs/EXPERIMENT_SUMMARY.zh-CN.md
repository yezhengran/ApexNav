# ApexNav 最终版实验总结

截至2026-11-19，用户选定 **Q8-C2-semantic-v2** 为后续开发的最终基准。三类487例新评测已独立验收；与原版其余513例合并后，**772/1000成功，总成功率77.20%**。这是有来源标记的混合结果，不是全1000重新运行v2。上述正式批次已停止，旧启动入口只作历史证据。2026-11-19用户另行授权重跑剩余旧编号333例，新批次按独立协议执行；完成前本页77.20%的已验收成绩保持。

实现与模块修改入口见[设计与维护说明](OBJECTNAV_DESIGN.zh-CN.md)；逐场景、逐episode、失败视频和完整验收过程见[三类最终报告](experiments/2026-11-17-qwen-semantic-v2-triclass487.zh-CN.md)。本文件负责汇总结论，不替代原始结果。

## 1. 最终结果与公平比较范围

固定HM3Dv2 val全局1–1000，seed=100，每例最多500步。SR、SPL、SoftSPL均按百分数展示；差值使用百分点。

| 同1000身份 | 成功数 | SR | SPL | SoftSPL | FP |
| --- | ---: | ---: | ---: | ---: | ---: |
| Q2同步复查基准 | 757 | 75.7000% | 37.5471% | 39.8402% | 111 |
| semantic-v1原完整结果 | 768 | 76.8000% | 37.5197% | 39.6228% | 159 |
| **最终混合结果** | **772** | **77.2000%** | **37.5789%** | **39.5630%** | **155** |

混合规则固定为：新v2的全部bed/couch/tv共487例无条件替换旧三类；其他chair/plant/toilet共513例原样引用，其中387成功。故成功数为 **385+387=772**。不按新旧成功择优，不覆盖原1000，也不把未完成尝试当成导航失败。

- 相对原v1：新增9成功、退化5，净增4；SR +0.40，SPL +0.0592，SoftSPL −0.0597个百分点。
- 相对Q2：新增44成功、退化29，净增15；SR +1.50，SPL +0.0319，SoftSPL −0.2772个百分点。
- FP是现有评测器的`result == "false positive"`标签，不等同于已人工确认的Qwen语义误识别。总FP仍比Q2多44，不能声称已全面解决误报。

| 历史关闭方向401–500 | 31/50，62.00% | 45/50，90.00% |

401–500旧组只有chair17、plant16、toilet17，新组只有bed16、couch16、tv18；类别构成完全不同，62%与90%不是编号修复的配对收益。全1000的两组身份、类别和运行时间也不同，不能按成功率差直接估计重跑增益。

最终结果尚保留旧编号333例：chair122例106成功（86.89%）、plant100例52成功（52.00%）、toilet111例89成功（80.18%）。其中35例实际触发候选比较，共56次调用；其余298例没有触发该接口。原v1前645例中的另312个bed/couch/tv身份已被新v2结果替换，所以统一最终编号只需考虑剩余333例，并非再跑全部645例。

2026-11-19用户已授权使用最终semantic-v2对这333个身份全部重跑，完整成功与失败都无条件纳入，其余667行原样保留。独立范围、来源和执行规则见[333例重测协议](experiments/2026-11-19-qwen-semantic-v2-id333.zh-CN.md)。编号修复的目的首先是避免图片序号/全局ID混淆，不能保证SR上升。只测触发过比较的35例可以诊断接口行为，但不能声称最终1000全部同协议重跑。

本地明细：`experiment_notes/semantic-v2-final-20261119/id-policy-summary.json`及`remaining-global-v1-episodes.json`。旧结果、共享账本和77.20%的最终成绩保持。

## 3. 实验演进与得到的结论

以下用于理解设计选择，不将不同集合的SR横向排名。命名与历史来源见[版本档案](OBJECTNAV_VERSIONS.zh-CN.md)；档案中的运行/恢复文字不构成新的启动授权。

| 阶段 | 主要变化 | 已有证据与限制 |
| --- | --- | --- |
| B0 / Q1 | 原导航与Qwen目标复查对照 | 同前50分别38/50、42/50；首次复查前已有轨迹差异，不是固定轨迹下的模型因果消融 |
| Q2 | 观测同步、候选身份/证据衔接及同步复查 | 完整1000为757成功，是后续同身份主对照 |
| Q3 / Q4 | 提前触发；融合资格触发与条件观测 | Q3前30为29/30；Q4旧失败子集只完成16/30、恢复2例，不能报告完整30或总体提升 |
| Q5 / Q6 | 朝向、置信度和高度/FOV约束观测 | Q6同前100为78成功，与Q2相同，SPL33.3052%低于Q2的40.6128%；观测绕行有代价 |
| Q8 / C2 | 严格Top5、环带多视角、备用拍摄半径与候选比较 | 逐项通过离线/小窗口验证；不能用这些窗口证明每个模块的独立全量贡献 |
| semantic-v1 | chair/couch、TV歧义提示；续跑中修复比较编号 | 完整1000为768成功，含两种编号协议，需保留源码分段 |
| semantic-v2 | 在v1上调整bed/couch/tv两类Qwen请求的语义指导 | 全487为385成功；全部替换三类后混合1000为772成功，正式结果已独立验收 |

当前保留条件式观测；可选前沿到点定向模块及其专用实验记录已按用户要求移除，semantic-v2仍为最终基准。未将历史Q5的加权分数公式或Q7观测开关笼统写成最终算法；最终行为以[设计说明](OBJECTNAV_DESIGN.zh-CN.md)和显式配置为准。

## 4. 可信度与适用边界

1. 本轮在val上开发和选择提示词，不是未见随机测试集上的泛化证据；未进行统计显著性或多seed实验。
2. v1旧487中312例使用`global_v1`、175例使用`image_order_v1`；新487全部使用后者。整体变化包含编号接口差异，不能称严格纯提示词消融。
3. 云端Qwen使用服务别名，不保证不同日期服务端权重固定；本地模型与构建指纹按原协议冻结。
4. 完整失败只计首个完整结果且不择优重跑。595第一次在PyTorch初始化时断言，无导航、Qwen、CSV或视频；按用户授权仅一次独立恢复，旧初始化现场保留，不计导航失败。
5. 还缺“关闭条件观测/关闭比较/不使用Top5”等同1000身份、同源码与模型条件下的完整消融，不能把净增15成功逐项分摊给模块。
