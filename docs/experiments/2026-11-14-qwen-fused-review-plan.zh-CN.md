# 融合置信度提前复查、物体最佳图与主动观测：实验对齐方案

## 1. 已对齐的三个独立环节

| 环节 | 用户要求 | 可检验的行为 |
| --- | --- | --- |
| 触发复查 | 用地图物体的融合置信度 | 同一物体达到原类别融合阈值后，可在行进中触发；不等待靠近物体或 STOP；不能用某张图的分数代替融合分数 |
| 选择输入图 | 独立、持续保存物体的最佳观测图 | 在同一地图物体绑定的可用目标 crop 中按单帧检测置信度取最高者；新图分数低不能仅因更新就覆盖最佳图 |
| 追加观测 | VLM 未通过且没有其他已通过物体时，寻找观测点位 | 规划安全观测点，实际移动/转向、补拍并复查；不能用“继续自然行进等下一帧”替代这个动作链 |

“通过”指 VLM 确认目标语义；地图融合分数高本身不等于已通过 VLM。“未通过”覆盖不确定与否定；两种原始回答必须分别记录。网络/API 异常不属于视觉未通过，继续按已有独立网络恢复规则处理。

## 2. 融合阈值与图像分数分离

用户已确认沿用原类别融合阈值。当前数值来自 `llm/answers/llm_answer_hm3d.txt`，由 `llm/answer_reader/answer_reader.py` 读取并传给地图：

| 任务类别 | 融合触发阈值 |
| --- | ---: |
| bed | 0.65 |
| couch | 0.60 |
| chair | 0.50 |
| tv | 0.45 |
| toilet | 0.45 |
| potted plant | 0.40 |

实现应读取原配置/类别来源，不在新模块硬编码另一套阈值。保留地图原有的目标类别、观测次数等有效性检查；不得仅凭浮点分数忽略原有资格条件。

- 融合分数 `fused_confidence`：决定物体是否具备自动首次复查资格。
- 单帧分数 `detector_score`：决定该物体哪张 crop 最佳，不再设置额外统一的 0.65 触发门槛。
- 检测器自身的 YOLO/DINO 检出阈值保持原样，不能与上述两个分数混称一个阈值。
- Qwen 输出仍为原结构化三段判断；不把它解释成上述任一置信度。

例如床的融合分数已达到 0.65，而其历史最佳可用 crop 分数为 0.62：若地图原有资格条件也满足，仍允许发送该 crop。反过来，crop 分数为 0.95、融合分数尚未达标，只保存图片，不因这张图高分就提前调用。

## 3. 一个地图物体绑定一份最佳图片记录

以 `(episode_token, candidate_id)` 为主键。候选 ID 必须来自 mapper 对原始 mask 的明确关联回执，不能由 Python 按空间距离猜测，也不能使用任务真值补绑。

这里的一对一是“每个地图候选簇有自己的最佳图片记录”，不是保证地图从不把一个真实物体拆成两个候选簇。不得通过离线真值消除这种地图误差。

机器人从扫描、行进到追加观测全程更新图片记录，独立于当前正在导航的物体、融合阈值是否达标以及是否已经请求 VLM。每条记录包含候选 ID、原始帧号、mask 索引、单帧分数、RGB/mask 来源、相机位姿、裁剪边界与关联回执。

建议沿用当前基本图像可用性限制：目标类别一致、mask 至少 64 像素、短边至少 8 像素，分数有限且在合法范围。通过这些检查后，**单帧分数最高优先**；只有分数相同才按完整性、面积、新近程度决胜。缺少合法绑定或可用图时保持等待证据，不发送别的物体的图。

一个物体的“最佳”是截至当前时刻已观察到的最佳。内存可有上限，但不能因为其他候选挤入原有 48 项缓存，就无记录地忘记仍有效物体的最佳图；实现应有可恢复的本地记录并记录淘汰原因。调用采用的来源另存不可变副本，命名必须同时区分物体、帧号与 mask，保留已有防覆盖约束。

地图候选失效、显式合并或拆分时必须依照地图身份关系处理并记录来源，不能把旧 ID 的图片静默归给新 ID。跨回合必须清空在线候选状态。历史高分图可以用于语义复查，但不能替代当前位姿和原有几何到达判定。

## 4. 首次复查、候选切换与寻找观测点位

预期流程如下；首次复查可以发生在扫描或行进途中：

```text
真实观测 → 地图融合/返回物体ID → 更新该物体的最佳crop
    ↓
融合资格满足 + 有可用绑定图 + 有调用额度
    ↓
VLM首次复查：发送该物体历史最佳可用crop
    ├─ 确认 → 标记通过，按原规划/到达规则导航
    └─ 不确定或否定
          ├─ 其他已确认且当前可导航的有效候选存在 → 优先导航该候选
          └─ 不存在 → 为未通过物体寻找安全观测点位
                       → 规划路径、实际移动/转向、补拍
                       → 发送新增视角中的最佳可用crop进行第二次复查
```

候选处理的实现约定：

1. “其他通过的物体”必须是同一任务目标类别、地图中仍有效、已获 VLM 确认且当前可以导航的候选；不能只检查历史上是否曾有一个确认结果。不可达或失效的通过候选不应永久压住其他候选的追加观测。
2. 同时存在多个具备首次复查资格的候选时，建议先处理这些候选的首次复查，再决定是否为未通过者绕行。这样不会因为遍历时先遇到未通过者，就忽略已经可确认的替代目标。调度排序和每次选择理由须可复现、可审计。
3. 由其他通过候选压住的追加观测记录应保留；如果替代目标随后失效或不可导航，可在原预算内重新考虑，不能重复开无限多段绕行。
4. 必须调用观测点位规划。沿用现有 `ActiveView::plan` / `ExplorationFSM::planInspection` 的对象尺度半径、可视性、已知自由空间、膨胀障碍和 A* 路径安全检查，输出实际观测目标点和路径。未找到安全点位必须记录原因并退出本次追加观测，不强行移动。
5. 导航到观测点位以及朝向目标的前进/转向均计入真实 Habitat 步数。允许途中得到合格的新证据后提前完成二次复查；若已确认即可结束追加观测，不要求为了录像走完整条路径。
6. 只有原地转向、因无安全点无法位移、实际发生前进补拍，三种情况必须分别统计。调用规划器不代表已经实际绕行，也不保证视角必然改善。

## 5. 二次复查与有界退出

以下采用原有预算作为本次方案的实现默认值，而非已经完成的新实验结果：每候选最多两次完成复查、最多一段追加观测；沿用最多 48 个观测动作、24 步无平移退出及每回合 500 步上限。模型、提示词、crop 生成方式、原脱困和几何到达规则保持。

第二次复查不能只是重发第一次的最高分图片。保留全历史最佳记录，同时在**首次调用后新增、与首次输入有足够视角差异的可用图片**中取检测分数最高的一张。新增视角的分数可能低于历史最佳；这是收集补充证据，不是覆盖历史最佳。具体新视角判据先沿用现有位移/转角/图像改善规则，并在事件中记清。

首次原始回答为否定时，仍按用户的“未通过”要求允许一次有界补拍；需要新增“首次否定、等待补充证据”的候选状态，不能直接沿用旧模式的永久终止状态，也不能把模型的否定回答改记成不确定。第二次回答仍分别保留确认、不确定、否定；缺图、找不到点位或观测预算用完，也需保留对应原因，不能伪造模型判断。

二次未通过或无法取得新证据时，结束该候选的追加观测，回到其他候选/探索与原有有界兜底。不能无限重复复查，不能把不确定直接标成确认。VLM 确认只更新语义状态，不直接发 STOP；是否到达仍由原几何规则决定。

传输失败仍独立于语义流程：保留已有每逻辑复核的 HTTP 重试、费用逐尝试预留与网络未完成回合恢复限制；不重置账本，不重跑完整导航失败。API 未完成不消耗“完成语义复查”计数，但其实际请求和费用必须留存。

## 6. 与既有实验的区别及实现入口

之前 `linked_early` 的单帧 0.65 实验采用“图片达标即复查，不确定后自然行进”，关闭了额外观测，**不是本方案**。前 30 回合的 29/30、63 次 VLM、0 个额外观测动作只能作为旧版本记录；原完整 1000 和原前 30 输出保持，不合并或改标为新方法。

核对当前代码发现，不能只把 `_may_inspect()` 改为 `True`：

- `vlm/early_review.py` 按单帧阈值筛图、关闭 inspection，并将确认/否定视为终止；需要独立新 profile，保留旧行为可复现。
- `ExplorationFSM::maybeReviewAutomatic()` 当前只消费图像就绪列表，没有按当前融合资格过滤，也没有“其他确认候选优先”的追加观测调度。
- `SelectedTargetReviewer::begin()` 对首次否定立即结束，需要独立的新策略状态，不修改旧实验的语义。
- `LinkedTargetReviewer` 已有 mapper 身份回执、最佳/最近图和逐调用来源；需要按本方案区分全历史最佳、第二视角最佳和可恢复的缓存生命周期。
- `ActiveView::plan` / `planInspection` 已能寻找安全观测点位，应复用并验证完整握手；自动复查后开始移动时，不能恢复一条移动前的陈旧导航路径。

以上是待实现工作。本次只提交设计文档；不把方案提交误记为功能已完成，也不启动新一轮评测。

## 7. 实现后的验收与实验建议

先做离线测试和独立构建，再录制实际动作链；长评测范围另按用户指令执行。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| crop 高分、融合未达标 | 持续保存最高分图，不调用 VLM |
| 融合达标、历史最高分 crop 低于 0.65 | 无额外单帧 0.65 门槛，发送正确物体的最佳可用图 |
| 同物体新图分数较低、同帧多个 mask、多候选、跨 episode | 最佳图不被低分覆盖，不串物体、不串 mask、不跨回合 |
| 超过热缓存上限后物体重新具备资格 | 正确恢复其最佳图及审计来源，不静默换用别的物体 |
| 首次确认 | 沿原规划接近并执行原到达判断，无追加观测 |
| 首次不确定或否定、没有其他通过候选 | 真正请求观测点位并产生补拍动作，原始判断保留 |
| 其他通过且可导航候选存在 | 优先该候选，未通过候选不启动绕行 |
| 其他确认候选失效/不可达 | 记录原因，在预算内重新考虑待处理候选 |
| 新视角分数低于旧最佳 | 保留旧最佳；二次复查使用新增视角中最高分图，不重发旧图 |
| 无安全点、无新图、额度用尽或网络异常 | 对应有界退出/网络恢复，无无限循环、跳回合或虚构模型判断 |

推荐完成后用同一前 30 固定身份、seed100、500步、独立目录与全程录像检查，不能选成功重跑结果替换失败。若进一步声称哪项机制改善效果，应分别对照原 Qwen、旧单帧提前复查、新融合触发与带条件追加观测，避免将多项改动全部归因于阈值。

指标除 SR/SPL/SoftSPL 外，必须分别列出：首次 VLM 步数及当时融合分数/阈值、实际 crop 单帧分数/来源步数、确认/不确定/否定次数、请求观测点位的回合、实际前进/转向数、二次复查回合、因其他已确认候选跳过追加观测的回合、HTTP 尝试/网络恢复/费用。视频需显示实际输入 crop、目标候选 ID、规划点位、动作及复查结果；不能把普通脱困动作标为主动观测。
